# H750 电机项目的 ODrive 移植约束

本文件是本项目的执行约束和验收入口。目标：在现有 STM32H750 电驱工程上，分阶段引入 ODrive 的控制组织、状态管理和诊断能力，使用 CAN、以太网、RS485 控制，保留可靠的硬件同步控制与独立保护路径。

## 0. 执行方式

- 开始任务时，先读取本文件及实际生效的父级、子目录指令。若项目已有 AGENTS.md，合并相关约束，不覆盖无关规则。
- 本文件不是已经通过验证的工程配置；所有检查项初始均未验收。不能把本文中的目标当成现有代码已实现的事实。
- 默认首次任务只完成“阶段 P0 现状审查”，不修改控制算法、PWM/ADC 配置、保护阈值或启动流程。用户已经明确要求实现时，先完成必要审查，再在授权范围内直接推进对应阶段，不重复索取确认。
- 后续工作根据用户指定范围执行；缺少某个参数时，只阻止依赖该参数的改动，继续完成不依赖它的审查、文档和验证。
- 不以删除断言、放宽阈值、屏蔽故障、伪造采样/校准结果、替换为无效桩函数的方式获得通过。
- 本文件的约束不得为了消除失败项而被自行改弱。确需变更时，记录技术原因、影响范围与依据；遵循用户已经授权的任务范围。
- 用户实际工程中的源码、构建配置、原理图和测量证据用于核查实现；发现它们与本文背景描述冲突时，记录冲突并解决，不能静默选一个版本。
- 不自行烧录、启用功率输出或操作实验电源；这些硬件动作按用户明确指令执行。

## 1. 背景与待核查参数

以下是用户给出的项目背景，尚未与当前仓库逐项核验：

| 项目 | 背景或目标 | 执行要求 |
| --- | --- | --- |
| 主控 | STM32H750VBT6，Keil、CubeMX 工程 | 从实际工程确认型号、编译器、启动文件、链接配置 |
| 控制 | 已有电机控制基础，计划适配 ODrive | 保留可工作的基准，先核查实际功能与测试条件 |
| PWM | 用户项目目标为 20 kHz | 确认实际时钟、中心对齐、RCR、ADC 触发、输出更新频率 |
| 电流与位置 | 电流采样、AD2S1210 旋变反馈 | 确认真实拓扑、通道、量程、符号、时序、有效性 |
| 通信 | CAN、LAN8742A 以太网、RS485 | 确认引脚、时钟、隔离、收发器和协议栈；不可假定三者已经可用 |
| Flash | 计划使用 W25Q32JVSSIQ | 分清参数存储、升级镜像、程序执行三种用途 |
| 保护 | 硬件过流/过压链、温度、欠压、失联、堵转、超速 | 依据当前板卡资料逐项核实，不以软件状态代替硬件关断证据 |
| 高压功率级 | 项目目标母线最高约 540 V、约 10 kW、六管 SiC | 不由功率除母线电压推断相电流限值；不自动选定保护阈值 |

必须查明并记录来源的未知项：

- 实际硬件版本、信号网络/管脚、有效电平、上电/复位默认状态。
- 母线与相电流采样比例、偏置、极性、滤波、ADC 分辨率与采样时间。
- 电机极对数、旋变角度与机械角关系、电角度零偏、转向、转矩常数与有效校准条件。
- PWM/ADC/控制周期、允许采样偏差、计算截止时间、最大关中断时间。
- 死区、最小有效脉宽、输出禁止时各门极输入的实际安全状态。
- 各保护阈值、回差、持续时间、动作方式、恢复条件；硬件短路覆盖范围及关断延迟。
- FreeRTOS/CMSIS 版本、tick、NVIC 分组、优先级位数、API 调用门槛及内存布局。
- 外部 Flash 的实际连接、分区、启动和下载方式；是否使用 XIP。

不能把 ODrive 原板的管脚、驱动器、采样比例、24 kHz PWM、8 kHz 控制周期或优先级数字直接当成 H750 目标配置。

## 3. 上下文与实时性约束

- [ ] CTX-01 为每个入口标注上下文：启动阶段、RTOS 任务、具体 IRQ、DMA/定时器硬件。函数经不同入口调用时，列出全部上下文。
- [ ] CTX-02 列出中断向量、实际 NVIC 抢占优先级/分组、触发源、调用链、可调用 API。区分 FreeRTOS 任务优先级、NVIC 数字和移位编码值。
- [ ] CTX-03 ISR 只使用当前内核/封装明确支持且优先级允许的 ISR API；不阻塞。高于系统调用门槛的 IRQ 不调用任何内核 API，包括 FromISR 版本。
- [ ] CTX-04 控制实时路径不等待互斥锁、网络发送、日志、Flash、动态内存分配或其他任务完成；输入不可用时执行有界失败处理。
- [ ] CTX-05 保留或建立 PWM/ADC 硬件同步的确定性控制路径。不得仅用普通 tick 延时或软件定时器替代电流环节拍。若调整执行模型，先给出时序预算和测量方案。
- [ ] CTX-06 实时路径和外设事务的关键等待均有明确上界和超时动作；普通任务在不持有关键资源且不阻碍其周期职责时，可以无限期阻塞等待事件。禁止把原板 ADC 的无超时 while 等待照搬到 H750；禁止在高优先级 ISR 中等待被它打断的低优先级写者。
- [ ] CTX-07 列出每段临界区究竟使用 PRIMASK、BASEPRI、调度暂停还是其他机制，说明它屏蔽谁；测量最长执行时间。临界区不包住外设等待或存储擦写。
- [ ] TIME-01 根据实际配置计算 PWM、采样、控制更新、速度环和 tick 频率。20 kHz PWM 的周期是 50 us，不代表控制周期和可用计算预算必定都是 50 us。
- [ ] TIME-02 为测量、角度、控制目标和输出生效定义时间戳关系、最大年龄/偏差和更新截止时间；需要角度时延补偿时注明依据。
- [ ] TIME-03 分别测量平均/最大控制耗时、触发抖动、最长关中断时间、通信高负载影响、超期计数；用周期计数器/硬件定时器/GPIO 等适合的方法，ISR 中不 printf。
- [ ] TIME-04 明确漏采样、漏迭代、数据超龄和超期时的故障动作。动作必须保证不继续使用未经许可的运动目标。

## 4. 状态管理与命令入口

- [ ] STATE-01 明确一个运行状态管理者，负责正常状态转换、校准流程、命令接受与运行许可。通信模块提交请求，实时路径执行已发布的有效目标。
- [ ] STATE-02 快速硬件关断与异步故障锁存可直接撤销输出许可；状态管理负责后续处置。不能要求硬件故障先通过普通命令队列或等待状态任务批准。
- [ ] STATE-03 对初始化、自检、待机、校准、运行、正常停止、故障等实际状态建立转换表：事件、前置条件、动作、超时、目标状态。复用现有合理状态，不为每个状态另建任务。
- [ ] STATE-04 启动前检查必要的采样/位置有效性、校准有效性、驱动就绪、母线/温度条件和无锁存故障；运行期间持续监测条件是否失效。
- [ ] STATE-05 校准不是每次 START 必须重做。明确结果何时有效、硬件/参数变化何时使其失效、校准的电流/电压/时间与允许运动范围。
- [ ] STATE-06 故障优先于启动、调速、校准和清错；并发请求不能覆盖故障。清错仅在条件满足后回到待机，必须等待新的有效启动请求，不恢复旧转速。
- [ ] STATE-07 正常减速停止、紧急解除输出、复位异常处理分开；结合回馈能量和实际功率级定义动作，不把它们统一成修改一个状态变量。
- [ ] CMD-01 CAN、以太网、RS485 使用统一命令语义和接受入口。每个运动请求带来源、命令类型、参数和可追踪序号/接收时间，标明哪些字段由板端产生。
- [ ] CMD-02 同一时刻只有一个运动控制来源；定义获得、释放、接管和失联规则。查询可并行；紧急停止权限另行定义，不因普通控制权而被延迟。
- [ ] CMD-03 只有当前有效控制来源、符合协议的命令/心跳才能续控制看门狗。查询、遥测或其他接口流量不能替失联控制者续命。控制失联监控和 MCU 独立看门狗分别设计。
- [ ] CMD-04 区分已收到、已接受、已应用、已拒绝。需要确认应用时，用实际控制路径更新的 applied_command_seq/epoch 等证据，不能仅以接收成功或唤醒任务为依据。
- [ ] CMD-05 明确顺序命令队列与最新目标邮箱的用途、容量和覆盖策略；队列满时返回错误/采取规定动作。紧急故障不依赖普通 FIFO 空位。故障或停止后使旧排队运动请求失效。
- [ ] CMD-06 参数检查覆盖非有限数、范围、单位、控制模式与状态合法性；明确速度单位 rpm/rev/s、机械角/电角、峰值/RMS 和转矩/电流关系。

## 5. 共享数据与快照合同

每项关键共享数据必须填写以下合同，不能只写 volatile 或“已加锁”：

| 字段 | 必填内容 |
| --- | --- |
| 名称与用途 | 具体对象、单位、有效范围 |
| 写入者 | 函数及任务/IRQ/DMA 上下文，是否存在多个写者 |
| 读取者 | 函数及上下文 |
| 发布与消费时刻 | 由什么事件发布，在哪个控制阶段读取 |
| 一致性与所有权 | 原子标量、短临界区复制、消息副本、有所有权的缓冲区或其他已证明机制 |
| 时间与身份 | frame_seq、command_seq、sample_timestamp、epoch、valid 等必要字段；不同含义不要共用计数器 |
| 生命周期 | 缓冲区可复用/释放时刻，DMA 完成和读者完成条件 |
| 失败规则 | 缺帧、超龄、重复、覆盖、校验失败、队列满时采取什么动作 |
| 证据 | 源码位置、并发推演、测试和测量 |

- [ ] DATA-01 逐项覆盖控制命令、状态请求、运行许可、故障锁存、相电流、母线、旋变角度/速度、dq 目标、PWM 更新、遥测、配置和各 DMA 缓冲区。
- [ ] DATA-02 电流、角度、目标和遥测帧的字段必须来自定义明确的一次发布。物理采样时刻可不同，但必须记录关联/补偿关系及允许偏差，不能靠相邻几行代码假定同步。
- [ ] DATA-03 实时路径每轮取得已发布且有效的数据副本；生产者不能在读者使用期间改写其内容。校验/临界区/发布屏障的具体实现要依据 MCU 和编译器核查。
- [ ] DATA-04 快照的序号和 valid 必须反映真实发布，不是“加了字段就一致”。atomic 索引不自动保证缓冲区生命周期；普通 memcpy 不自动形成原子快照。
- [ ] DATA-05 禁止 ISR 读者自旋等待低优先级任务写者完成 seqlock/奇偶序号更新；只允许有界读取。读取有上界仍须满足实际编译器/平台的并发访问和发布顺序要求，序号一致检查不自动消除数据竞争。失败后按数据安全性使用仍有效的上一帧，或执行缺帧/超龄处理，不无期限沿用旧值。
- [ ] DATA-06 不将 volatile、OutputPort、Fibre Property 或单个 bool 当成完整同步方案；对 64 位字段和多字段结构单独核查原子性。
- [ ] DATA-07 信号/通知只说明事件按所选语义发生；不自动保存数据、不必然逐次计数、不代表输出已经应用。说明清除、计数、合并和丢事件规则；需要逐帧数据时另设有界缓冲。
- [ ] DATA-08 遥测读取已发布的快照；明确丢帧/降采样策略。日志及状态上报不得阻塞保护或控制路径，不逐控制周期强制发送全部原始数据。
- [ ] DATA-09 输入模式、反馈数据源、PI 参数和控制律切换采用明确的停机或受控交接流程；通信属性不能无约束改写运行中的内部对象。

## 6. H750 外设和内存约束

- [ ] HW-01 对照实际网络表/原理图与 CubeMX，建立引脚、复用、外设实例、DMA、时钟和有效电平表；不能从旧聊天或 ODrive 原板推断真实连接。
- [ ] HW-02 核查 ADC 触发源、序列、通道间偏差、采样时间、模拟建立时间、完成标志、过载和丢样检测；采样窗口依据实际霍尔/分流拓扑确定。
- [ ] HW-03 核查定时器中心对齐、互补极性、死区、最小脉宽、预装载、更新事件、MOE/AOE/BKIN 或等效机制；禁止通过修改 CCR 为零/50% 来冒充完整关断。
- [ ] HW-04 AD2S1210 接入必须覆盖读取时序、角度分辨率、转向、电角换算、时间戳、故障读取和最大跟踪条件；不得把其他 SPI 编码器的协议直接套用。核查 LOT/DOS 实际是否可读。
- [ ] MEM-01 对每个 DMA 确认其可访问的 RAM 区域、链接位置、缓冲区对齐和数据宽度；不能把所有 H750 RAM 当成对所有 DMA 同等可达。
- [ ] MEM-02 依据实际 DCache/MPU 配置，说明每个 DMA 缓冲区的缓存策略和必要的 clean/invalidate 顺序、缓存行边界与所有权；volatile 不替代缓存维护。
- [ ] MEM-03 不让 DMA 引用已退出函数的局部对象，不提前复用仍在发送/接收的数据。避免缓存行维护破坏相邻对象；验证 ETH 描述符和数据区。
- [ ] MEM-04 检查任务/队列/信号量创建结果；记录栈单位、任务栈余量和堆余量。原生 FreeRTOS 与 CMSIS 版本分别核查，不混用对象句柄或栈参数单位。
- [ ] MEM-05 尽量在初始化分配所需资源；禁止在 ISR/高频控制路径动态分配。跨任务/中断的大数组或结构访问必须有一致性合同。

## 7. 保护与异常处理

- [ ] SAFE-01 输出默认禁止；上电、复位、调度器尚未启动、初始化失败时，硬件和软件均维持规定的安全状态。实际关断电平与硬件能力需验证。
- [ ] SAFE-02 硬件过流/过压等快速链路独立于 RTOS、通信和日志；软件记录/恢复逻辑不能成为硬件关断前置条件。
- [ ] SAFE-03 明确相电流保护与桥臂短路的覆盖范围、检测到关断的总延迟；没有器件和波形依据时不得宣称已满足 SiC 短路保护。
- [ ] SAFE-04 对欠压、过压、过温、位置无效、失联、堵转、超速、采样异常和时序超期定义阈值来源、回差/持续时间、动作与恢复规则。未知阈值保持 UNKNOWN，不伪造可运行默认值。
- [ ] SAFE-05 故障锁存/清除不得丢失并发故障；解除输出后陈旧命令、旧许可和未完成校准不能重新打开输出。恢复需建立新的有效运行代次。最终 arm/使能输出的交接处必须核对当前故障、许可与运行代次，并证明“检查后故障到达”不会造成错误重新使能；仅在状态任务中提前检查一次不够。
- [ ] SAFE-06 断言、HardFault、栈溢出、内存分配失败和看门狗复位路径明确撤销输出的办法；不依赖网络、Flash、互斥锁或故障时可能不可用的调度器。
- [ ] SAFE-07 独立看门狗喂狗基于关键功能健康，不能仅因 Idle 或一个线程仍在运行就证明系统健康；健康条件和超时动作必须明确定义。
- [ ] SAFE-08 正常制动、紧急关断、母线回馈和泄放分别考虑；停止 PWM 不等于母线能量已经消失。无硬件资料时不生成制动电阻/斩波器的虚构参数。

## 8. 通信和存储

- [ ] IO-01 CAN 明确标准/扩展帧、ID、长度、字节序、缩放、单位和超时；H750 FDCAN 驱动不得直接套用 F405 bxCAN 寄存器实现。
- [ ] IO-02 TCP 按字节流处理拆包/粘包并限定长度、解析时间和缓冲容量；UDP 如使用则定义序号、重复/乱序和超时规则。采用项目实际 LwIP API 的线程约束。
- [ ] IO-03 RS485 明确帧边界、长度、校验、接收恢复、DE/RE 极性与发送真正完成时刻；启动 DMA 不代表总线发送结束。
- [ ] IO-04 每路接收/解析/发送都有容量、超时和过载策略；畸形、洪泛或断开的通信不拖死控制路径。控制接口失联不由其他接口的查询流量掩盖。
- [ ] STORE-01 确认 W25Q32 的实际使用模式；只保存参数不会自动扩展可执行程序空间。XIP/搬入 RAM 执行需独立的启动、链接、加载器与调试验证。
- [ ] STORE-02 参数具有版本、长度、完整性校验和掉电一致性设计；保存条件由状态管理验证并互锁，防止检查后又被其他请求启动。
- [ ] STORE-03 若程序从同一 Flash 执行，擦写前证明所有相关执行路径、中断和常量访问仍安全。仅分区或仅停机不自动解决同芯片擦写与取指冲突。
- [ ] STORE-04 不在关键 ISR 中擦写 Flash。后台保存/日志过载有明确退让与丢弃策略，不能反向阻塞控制或保护。

## 9. 检查、断言和验证证据

每个检查 ID 分别记录 SRC（源码/静态）、BUILD（编译链接）、HOST（主机逻辑测试）、HW（上板）结果；不适用的层级写 N/A 并说明理由。

状态定义：

- PASS：指定层级检查已执行，满足明确标准，有可复查证据。
- FAIL：检查已执行，发现不符合要求。
- UNKNOWN：缺少参数、需求或依据，无法判断标准或结论。
- NOT_RUN：检查和标准明确，但尚未执行。
- N/A：确实不适用，附理由；不能用它跳过必要验证。

docs/VALIDATION.md 中使用以下记录格式：

```text
ID: DATA-03
Git commit / 工作区差异:
涉及文件和函数:
预期行为与通过标准:
SRC: NOT_RUN
BUILD: NOT_RUN
HOST: NOT_RUN
HW: NOT_RUN
执行命令、工具版本与构建配置:
证据路径、输出摘要、硬件版本与实验条件:
失败原因或待执行步骤:
残余风险和依赖的未知项:
```

- [ ] VERIFY-01 编译期检查适用于类型、常量范围、布局与确定的配置关系；运行期断言适用于可观测的不变量。不能把硬件阈值未确认的问题伪装成静态断言已解决。
- [ ] VERIFY-02 运行期安全故障必须有明确处置，不能只依赖可能被关闭的 configASSERT。断言中不写必需的业务副作用，防止发布构建去掉检查后丢失动作。
- [ ] VERIFY-03 实现相应功能时，增加必要的逻辑测试：并发命令/控制权、故障与启动同时到达、清错后的旧命令、失联、满队列、无效或过期采样；测试行为而非复制实现。
- [ ] VERIFY-04 上板分别验证 PWM/死区/采样相位、角度与电流方向、真实关断链、最坏控制耗时和通信高负载。没有板卡或仪器时标记 NOT_RUN，并给出步骤与标准。
- [ ] VERIFY-05 发现控制超期、方向/量程异常、反馈无效、保护未生效时，暂停依赖它的上板推进，保留故障证据；可以继续不依赖该项的代码审查和修复。
- [ ] VERIFY-06 不把主机测试、仿真、静态分析或一次编译成功写成上板通过；不把“断言代码已加入”写成“断言已触发验证”。
- [ ] VERIFY-07 每次交付列出本次通过、失败、未知、未执行的相关 ID；PASS 必须关联本次提交或确切差异及其执行证据。源码变更后重新评估受影响证据。

## 10. 分阶段推进与交付

| 阶段 | 目标 | 交付/推进条件 |
| --- | --- | --- |
| P0 | 审查现有工程 | 现状图、共享数据表、未知项、基准构建记录与阶段计划齐全 |
| P1 | 上下文、资源和数据接口 | 关键数据所有权与同步合同明确，初始化、输出禁止与故障入口可核查 |
| P2 | 采样、角度、PWM 和时序 | 编译与逻辑检查完成；对应低压上板证据单独记账，缺失项不冒充通过 |
| P3 | 状态管理、命令和保护 | 校准/启停/故障/清错/控制权/失联行为一致，有拒绝与失败路径证据 |
| P4 | 通信上报与存储 | 过载、断线、掉电和 XIP 限制有处理，不阻塞控制 |
| P5 | 分级硬件验收 | 按用户指定的电压、负载和测试范围执行；高压上电不由代码审查代替授权与实测 |

- 每次只实现用户授权范围内的最小完整变更；保持工程可审查，避免同时重写算法、外设、RTOS 和协议。
- 不强制一次实现全部高级功能。MTPA、弱磁、无感、IADRC 等在用户明确纳入范围前不顺带加入。
- 如不能编译，给出精确的缺失条件、可执行验证步骤和已完成的静态检查，不修改底层实现来掩盖环境问题。
- 文档中的待测值不能成为会自动启用功率输出的默认配置。
- 每次汇报：修改内容、原因、影响的上下文/数据合同、已执行检查、未执行检查、失败/未知项和下一项可推进工作。

## 11. ODrive 参考版本与需要保留的区分

参考来源为官方仓库 odriverobotics/ODrive，fw-v0.5.6，commit a308314ed2ca613164b81e7bbdfacc53cd1859ff。若工程使用其他版本，先核查差异。

- Board/v3 的采样 IRQ 与软件触发控制 IRQ 分开；电流获取、组件更新、实际 PI/SVM/PWM 输出是控制 IRQ 内的不同阶段，不能仅凭函数名判定上下文。
- Axis 的控制迭代信号用于同步进度，不携带测量帧；信号发出时外层中断仍可能有未完成的输出阶段。
- OutputPort 的 reset/present 管理本轮新鲜度，不自动提供跨上下文线程安全。
- 原版通信事件队列不等于统一电机命令队列；Fibre 属性层不自动提供整组命令原子性。
- 原版 PRIMASK 临界区、8 kHz 控制时序、传感器和存储流程不是本板必须照抄的目标。
- 迁入源码时保留所需版权和许可证声明，记录本地修改与来源。
