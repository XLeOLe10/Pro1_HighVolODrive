```markdown
# FOC_T 团队工作约定

- 使用中文沟通；开始任务先确认仓库根目录、当前分支和未提交修改。
- 先阅读相关源码，并按需要追踪调用者、被调用者、共享数据、中断和主循环关系；结论标注文件/函数位置，未知项明确列出。
- 每个可独立验收的功能维护一份 docs/specs 下的规格，先写清目标、范围、接口与单位、重要约束、验收场景和验证方法。
- 规格先交由用户审阅。用户明确确认后，在已批准范围内自主实施，不为同一决定反复请求确认。
- 如果新发现改变了已批准的目标、接口或重要约束，先更新规格并请求复审；普通实施细节由 AI 自行处理。
- 小变更使用短规格；同一功能持续更新原规格，避免每轮对话生成重复文档。
- 每份规格维护状态：待审阅 → 已确认/实施中 → 实现完成待验收 → 已验收；用户确认记录和未完成事项保留在同一份规格中。
- 保留用户已有改动，按小任务实施；控制逻辑、无关重构和批量格式化分别处理。
- 验证与变更匹配：纯文本检查内容与 Git 差异；控制或数学逻辑根据影响安排测试、目标编译及必要的上板验证。
- 完成时报告实际改动、已执行验证、结果和未验证项；编译通过与上板通过分别记录。
- 默认由用户进行暂存、提交、推送、PR 和合并；用户明确授权 AI 代操作时按该授权执行。
- 用户的当前明确指令优先于本文件；其他工程和工具的约定不自动套用到本仓库。
```
